# Session 2026-09-03 — pod UX design: agent access, observability, in-pod pi

## Goal

Make the pod usable as (1) an OpenAI/Anthropic-format backend for standard coding agents on the
laptop, (2) observable from the laptop, (3) chattable directly via the pi coding harness installed
in the pod. Research-only sitting; no resources created.

## What I did

Four parallel research agents (SGLang API surface, pi harness, pod observability stack, coding-agent
client UX), synthesized into the design canvas
`~/.cursor/projects/Users-marcopesani-Projects-selfhost/canvases/pod-ux-design.canvas.tsx`.
Updated `scripts/ssh-tunnel.sh` to forward the observability port alongside the API.

Key findings (all source-verified 2026-09-03; detail in the canvas):

- **No adapter needed.** Current SGLang natively serves `/v1/chat/completions`, `/v1/responses`
  (Codex CLI now requires Responses wire; chat wire_api removed Feb 2026), and `/v1/messages` +
  `/v1/messages/count_tokens` (Anthropic). Claude Code connects with env vars only; no LiteLLM.
- **Cursor is architecturally disqualified**: BYOK requests originate from Cursor's cloud backend
  and loopback base URLs are rejected server-side. Excluded — consistent with ADR-003/012.
- **pi** is now `@earendil-works/pi-coding-agent` (repo `earendil-works/pi`, MIT, v0.84.x; npm name
  `@mariozechner/pi` is an unrelated vLLM pod tool — do not install by mistake). Custom
  OpenAI-compatible provider via `~/.pi/agent/models.json` with per-model `contextWindow: 1048576`,
  `compat.supportsDeveloperRole: false`; handles GLM `reasoning_content`; `PI_OFFLINE=1` silences
  update checks + install telemetry. Runs in tmux on the pod, talks only to 127.0.0.1:8000.
- **Observability stack**: SGLang `--enable-metrics` (TTFT/e2e histograms, tok/s, queue depth, KV
  `token_usage`, spec-decode `spec_accept_length`) + `nvidia_gpu_exporter` (NVML; dcgm-exporter
  needs privileges Runpod does not grant) + `node_exporter` (restricted collectors; fs collector
  watches `/workspace` during the weights download) + VictoriaMetrics single binary with built-in
  vmui UI on :8428 (~100–200 MB total; Prometheus+Grafana judged oversized). One ssh -L command
  forwards 8000 + 8428; exporters stay scrape-only inside the pod.
- **CVE-2026-15977 (sglang#37457, fix open)**: `/get_server_info` and the startup log line return
  the plaintext `--api-key`. Consequences wired into the design: never scrape `/get_server_info`
  into a TSDB, `/workspace/logs` mode 700 (rotatelogs wrapper; SGLang has no `--log-file`),
  optional distinct `--admin-api-key`, never reuse `GLM_API_KEY`.
- `/metrics` and `/health*` bypass bearer auth by design (hard-coded) — acceptable loopback-only;
  they carry no prompt content.
- Privacy: request-content logging is off unless `--log-requests` is passed;
  `SGLANG_DISABLE_REQUEST_LOGGING` does not control the request logger (sglang#22622 drift).
- Model-behavior risk: sglang#36669 — GLM-5.3-Flash thinking degeneration (`!` loops) under complex
  system prompt + multi-tool agentic load. First-sitting smoke test required on the NVFP4
  checkpoint before blessing agentic clients. Keep temperature ≥ ~1 for tool calls.
